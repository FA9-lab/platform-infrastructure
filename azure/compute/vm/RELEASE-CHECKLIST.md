## 1. Change Review

- [ ] Changes have been reviewed and merged.
- [ ] Consumer-facing contract compatibility has been assessed.
- [ ] Version increment follows the release policy.
- [ ] Breaking changes and migration requirements are documented.

## 2. Technical Validation

- [ ] Terraform formatting and validation pass, where applicable.
- [ ] Relevant automated workflow checks pass.
- [ ] Terraform Plan has been reviewed against a representative deployment.
- [ ] Resource creation, update, or replacement impact is documented.
- [ ] Security and governance implications have been reviewed.

## 3. Recovery Readiness

- [ ] Rollback or forward-fix approach is documented.
- [ ] State and resource recovery implications are understood.
- [ ] Any destructive changes have explicit approval requirements.

## 4. Release Publication

- [ ] Release reference identifies a reviewed commit.
- [ ] Release notes describe changes and compatibility.
- [ ] Upgrade instructions are available to deployment owners.
- [ ] Release reference has been verified after publication.

## 5. Consumer Adoption

- [ ] Initial rollout environment is identified.
- [ ] Deployment owners are informed of the release.
- [ ] Adoption is tracked across deployment repositories.
- [ ] Upgrade failures have an assigned escalation owner.
